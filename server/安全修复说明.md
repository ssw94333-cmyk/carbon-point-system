# 安全修复说明

## 问题
Git历史中包含阿里云AccessKey敏感信息，GitHub阻止了推送。

## 解决方案

### 1. 配置文件分离
- `application.yml` - 使用占位符，可以提交
- `application-dev.yml` - 包含真实配置，不提交（已加入.gitignore）
- `application-dev.yml.example` - 配置模板，可以提交
- `application-prod.yml.example` - 生产环境模板，可以提交

### 2. 使用步骤

**开发环境：**
1. 复制 `application-dev.yml.example` 为 `application-dev.yml`
2. 修改其中的配置信息（数据库密码、OSS密钥等）
3. 启动项目（默认使用dev环境）

**生产环境：**
1. 复制 `application-prod.yml.example` 为 `application-prod.yml`
2. 修改其中的配置信息
3. 启动时指定环境：`java -jar app.jar --spring.profiles.active=prod`

### 3. 清理Git历史

如果之前已经提交了敏感信息，需要清理Git历史：

```bash
# 方法1：使用git filter-branch（适用于小仓库）
git filter-branch --force --index-filter \
  "git rm --cached --ignore-unmatch server/src/main/resources/application-dev.yml" \
  --prune-empty --tag-name-filter cat -- --all

# 方法2：使用BFG Repo-Cleaner（推荐，更快）
# 下载 https://rtyley.github.io/bfg-repo-cleaner/
java -jar bfg.jar --delete-files application-dev.yml

# 强制推送
git push origin --force --all
```

### 4. 重新生成AccessKey

**重要：** 由于AccessKey已经泄露到Git历史中，建议：
1. 登录阿里云控制台
2. 删除泄露的AccessKey
3. 创建新的AccessKey
4. 更新本地的 `application-dev.yml` 配置

## 注意事项

1. `.gitignore` 已更新，包含敏感配置文件
2. 所有包含真实密钥的文件都不应提交到Git
3. 团队成员需要自己创建 `application-dev.yml` 文件
4. 生产环境配置应通过安全的方式部署，不要提交到代码仓库
