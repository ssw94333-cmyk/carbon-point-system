# 行为管理模块实现说明

## 概述

行为管理模块已完整实现，包含用户端和管理端的所有功能。该模块实现了碳行为记录的提交、审核、统计等核心功能。

## 已实现的功能

### 用户端功能
1. ✅ 获取行为规则列表
2. ✅ 获取行为规则详情
3. ✅ 提交行为记录
4. ✅ 获取我的行为记录（支持分页和筛选）
5. ✅ 获取行为记录详情
6. ✅ 删除行为记录（仅待审核状态）
7. ✅ 获取行为统计数据

### 管理端功能
1. ✅ 获取待审核列表（支持分页和筛选）
2. ✅ 审核行为记录（通过/拒绝）
3. ✅ 获取所有行为记录（支持分页和筛选）
4. ✅ 创建行为规则
5. ✅ 更新行为规则
6. ✅ 删除行为规则
7. ✅ 获取管理员统计数据

## 核心业务逻辑

### 1. 提交行为记录
- 验证规则是否存在且启用
- 验证数值范围（minValue ~ maxValue）
- 检查每日积分限制（maxPointsPerDay）
- 验证证明材料（needProof=1时必须上传）
- 自动计算减碳量和积分
- 创建记录，初始状态为待审核（auditStatus=0）

### 2. 审核行为记录
**审核通过时：**
- 更新记录状态为"审核通过"
- 增加用户 current_points
- 增加用户 total_points
- 增加用户 total_carbon_reduction
- 记录积分变动历史（points_change_record表）
- 记录审核人和审核时间

**审核拒绝时：**
- 更新记录状态为"审核拒绝"
- 必须填写拒绝原因
- 不增加用户积分和减碳量

### 3. 删除行为记录
- 只能删除自己的记录
- 只能删除待审核状态（auditStatus=0）的记录

### 4. 删除行为规则
- 检查是否有关联的行为记录
- 如果有记录，不允许删除

## 数据库表

### behavior_rule（行为规则表）
- id: 主键
- behavior_name: 行为名称
- behavior_type: 行为类型（英文标识，唯一）
- unit: 单位
- carbon_reduction_per_unit: 每单位减碳量(kg)
- points_per_unit: 每单位积分
- min_value: 最小数值限制
- max_value: 每日最大数值限制
- max_points_per_day: 每日最大积分限制
- need_proof: 是否需要证明：0-否，1-是
- status: 状态：0-禁用，1-启用
- sort_order: 排序
- description: 规则说明

### carbon_behavior_record（行为记录表）
- id: 主键
- user_id: 用户ID
- behavior_type: 行为类型
- behavior_name: 行为名称
- behavior_value: 行为数值
- carbon_reduction: 减碳量(kg)
- points: 积分
- description: 行为描述
- proof_image: 证明材料图片URL（多张用逗号分隔）
- audit_status: 审核状态：0-待审核，1-通过，2-拒绝
- audit_user_id: 审核人ID
- audit_remark: 审核备注
- audit_time: 审核时间

### points_change_record（积分变动记录表）
- id: 主键
- user_id: 用户ID
- change_type: 变动类型：1-增加，2-减少
- source_type: 来源类型：碳行为、管理员调整等
- source_id: 来源ID
- points: 变动积分数
- balance_before: 变动前余额
- balance_after: 变动后余额
- remark: 变动说明

## 权限控制

### 拦截器配置（WebConfig.java）
1. **AuthInterceptor**: 所有 `/api/**` 接口需要登录（除了注册和登录）
2. **AdminInterceptor**: 管理端接口需要管理员权限
   - `/api/behavior/audit/**` - 行为审核
   - `/api/behavior/admin/**` - 管理员统计等功能
3. **RuleManagementInterceptor**: 规则管理权限
   - GET 请求放行（所有用户可查看）
   - POST/PUT/DELETE 需要管理员权限

## API接口列表

### 用户端
- GET `/api/behavior/rules` - 获取行为规则列表
- GET `/api/behavior/rules/{id}` - 获取行为规则详情

- GET `/api/behavior/record` - 获取我的行为记录
- GET `/api/behavior/record/{id}` - 获取行为记录详情
- DELETE `/api/behavior/record/{id}` - 删除行为记录
- GET `/api/behavior/statistics` - 获取行为统计数据

### 管理端
- GET `/api/behavior/audit/list` - 获取待审核列表
- PUT `/api/behavior/audit/{id}` - 审核行为记录
- GET `/api/behavior/admin/records` - 获取所有行为记录
- POST `/api/behavior/rules` - 创建行为规则
- PUT `/api/behavior/rules/{id}` - 更新行为规则
- DELETE `/api/behavior/rules/{id}` - 删除行为规则
- GET `/api/behavior/admin/statistics` - 获取管理员统计数据

## 注意事项

1. **事务处理**: 审核通过操作使用了 `@Transactional` 注解，确保数据一致性
2. **数据验证**: 所有DTO都使用了 `@Validated` 注解进行参数验证
3. **权限控制**: 通过拦截器实现了细粒度的权限控制
4. **错误处理**: 使用统一的异常处理机制
5. **日期格式**: 统一使用 `yyyy-MM-dd HH:mm:ss` 格式
6. **分页查询**: 使用 MyBatis-Plus 的 Page 插件
