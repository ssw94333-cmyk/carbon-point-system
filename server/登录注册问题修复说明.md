# 登录注册 403 错误修复说明

## 问题描述
前端调用 `/api/user/register` 和 `/api/user/login` 接口时返回 403 错误。

## 问题原因

### 1. CORS 预检请求被拦截
浏览器在发送跨域 POST 请求前会先发送 OPTIONS 预检请求，但拦截器没有放行 OPTIONS 请求。

### 2. 拦截器路径配置问题
`AdminInterceptor` 配置的路径 `/api/user/{id}` 会匹配到 `/api/user/login`，导致登录请求被误判为需要管理员权限。

## 修复内容

### 1. AuthInterceptor.java
添加了 OPTIONS 请求的放行逻辑：
```java
// 放行 OPTIONS 预检请求
if ("OPTIONS".equalsIgnoreCase(request.getMethod())) {
    return true;
}
```

### 2. AdminInterceptor.java
同样添加了 OPTIONS 请求的放行逻辑。

### 3. WebConfig.java
简化了 `AdminInterceptor` 的路径配置，只拦截明确需要管理员权限的接口：
- `/api/user/list` - 用户列表
- `/api/behavior/audit/**` - 行为审核
- `/api/behavior/rules` - 规则管理

对于 `/api/user/{id}` 等接口，权限检查在 Service 层完成。

## 测试步骤

1. 重启后端服务器
2. 打开前端页面
3. 测试注册功能
4. 测试登录功能

## 预期结果
- 注册和登录功能正常工作
- 不再出现 403 错误
