## 管理员功能列表

### 1. 用户管理

#### 1.1 获取用户列表

**接口**: `GET /api/user/list`

**权限**: 仅管理员

**请求参数**:
- `page`: 页码（默认1）
- `size`: 每页数量（默认10）
- `username`: 用户名（可选，模糊查询）
- `phone`: 手机号（可选，模糊查询）
- `userType`: 用户类型（可选，0-普通用户，1-管理员）
- `status`: 状态（可选，0-禁用，1-启用）

**示例**:
```bash
GET http://localhost:8080/api/user/list?page=1&size=10
Authorization: Bearer {管理员token}
```

**响应示例**:
```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "records": [
      {
        "id": 2,
        "username": "zhangsan",
        "phone": "13800138001",
        "nickname": "张三",
        "avatar": "/avatar/user1.jpg",
        "email": "zhangsan@example.com",
        "userType": 0,
        "status": 1,
        "totalPoints": 1500,
        "currentPoints": 800,
        "totalCarbonReduction": 125.50,
        "createTime": "2026-01-13 08:00:00"
      }
    ],
    "total": 7,
    "size": 10,
    "current": 1,
    "pages": 1
  }
}
```

#### 1.2 获取用户详情

**接口**: `GET /api/user/{id}`

**权限**: 仅管理员

**示例**:
```bash
GET http://localhost:8080/api/user/2
Authorization: Bearer {管理员token}
```

#### 1.3 修改用户状态

**接口**: `PUT /api/user/{id}/status`

**权限**: 仅管理员

**请求参数**:
- `status`: 状态（0-禁用，1-启用）

**示例**:
```bash
PUT http://localhost:8080/api/user/2/status?status=0
Authorization: Bearer {管理员token}
```

**说明**: 禁用用户后，该用户将无法登录系统

#### 1.4 编辑用户信息

**接口**: `PUT /api/user/{id}`

**权限**: 仅管理员

**请求体**:
```json
{
  "nickname": "新昵称",
  "email": "newemail@example.com",
  "phone": "13900139000"
}
```

**示例**:
```bash
PUT http://localhost:8080/api/user/2
Authorization: Bearer {管理员token}
Content-Type: application/json

{
  "nickname": "张三三",
  "email": "zhangsan@example.com"
}
```

### 2. 行为管理

#### 2.1 获取待审核行为记录列表

**接口**: `GET /api/behavior/audit/list`

**权限**: 仅管理员

**请求参数**:
- `page`: 页码（默认1）
- `size`: 每页数量（默认10）
- `userId`: 用户ID（可选）
- `behaviorType`: 行为类型（可选）
- `startTime`: 开始时间（可选）
- `endTime`: 结束时间（可选）

**示例**:
```bash
GET http://localhost:8080/api/behavior/audit/list?page=1&size=10
Authorization: Bearer {管理员token}
```

#### 2.2 审核行为记录

**接口**: `PUT /api/behavior/audit/{id}`

**权限**: 仅管理员

**请求体**:
```json
{
  "auditStatus": 1,
  "auditRemark": "审核通过"
}
```

**字段说明**:
- `auditStatus`: 审核状态（1-审核通过，2-审核拒绝）
- `auditRemark`: 审核备注（可选）

**示例 - 审核通过**:
```bash
PUT http://localhost:8080/api/behavior/audit/10
Authorization: Bearer {管理员token}
Content-Type: application/json

{
  "auditStatus": 1,
  "auditRemark": "审核通过"
}
```

**示例 - 审核拒绝**:
```bash
PUT http://localhost:8080/api/behavior/audit/10
Authorization: Bearer {管理员token}
Content-Type: application/json

{
  "auditStatus": 2,
  "auditRemark": "证明材料不清晰，请重新上传"
}
```

#### 2.3 创建行为规则

**接口**: `POST /api/behavior/rules`

**权限**: 仅管理员

**请求体**:
```json
{
  "behaviorType": "metro",
  "behaviorName": "地铁出行",
  "unit": "次",
  "carbonReductionPerUnit": 3.0000,
  "pointsPerUnit": 25,
  "minValue": 1.00,
  "maxValue": 10.00,
  "maxPointsPerDay": 250,
  "needProof": 0,
  "sortOrder": 10,
  "description": "乘坐地铁代替开车，每次减少3千克碳排放，获得25积分"
}
```

#### 2.4 更新行为规则

**接口**: `PUT /api/behavior/rules/{id}`

**权限**: 仅管理员

**请求体**: 同创建行为规则

#### 2.5 删除行为规则

**接口**: `DELETE /api/behavior/rules/{id}`

**权限**: 仅管理员

**注意**: 已被使用的规则不允许删除

## 常见问题

### Q1: 为什么看不到用户列表？

**可能原因**:
1. 未使用管理员账号登录
2. Token已过期
3. 请求头中未携带Token

**解决方法**:
1. 确认使用admin账号登录
2. 重新登录获取新的token
3. 检查请求头：`Authorization: Bearer {token}`

### Q2: 为什么提示"无权限访问"？

**原因**: 当前登录的不是管理员账号

**解决方法**: 使用admin账号登录

### Q3: 审核通过后用户积分没有增加？

**检查步骤**:
1. 查看数据库user表的current_points字段
2. 查看points_change_record表是否有新记录
3. 检查控制台是否有异常日志

### Q4: 如何创建新的管理员账号？

**方法1**: 直接在数据库中修改
```sql
UPDATE user SET user_type = 1 WHERE username = '用户名';
```

**方法2**: 注册新用户后，使用admin账号修改（需要后端添加修改用户类型的接口）

## 数据库查询验证

### 查看所有用户
```sql
SELECT id, username, nickname, user_type, status, current_points, total_carbon_reduction 
FROM user 
ORDER BY create_time DESC;
```

### 查看待审核的行为记录
```sql
SELECT cbr.*, u.username 
FROM carbon_behavior_record cbr
LEFT JOIN user u ON cbr.user_id = u.id
WHERE cbr.audit_status = 0
ORDER BY cbr.create_time ASC;
```

### 查看积分变动记录
```sql
SELECT pcr.*, u.username 
FROM points_change_record pcr
LEFT JOIN user u ON pcr.user_id = u.id
ORDER BY pcr.create_time DESC
LIMIT 10;
```

## 注意事项

1. **管理员权限**: 所有管理员接口都需要userType=1的用户才能访问
2. **Token有效期**: 默认24小时，过期后需要重新登录
3. **审核操作**: 审核通过后会自动发放积分，不可撤销
4. **用户状态**: 禁用用户后，该用户无法登录，但不影响已有数据
5. **规则删除**: 已被使用的规则不允许删除，避免数据不一致
